# Home Assistant

Home Assistant runs from the `home-assistant-config` PVC and uses the
`home-assistant-db` CloudNative-PG cluster for recorder history.

## Runtime configuration

Recorder and reverse-proxy settings live in `/config/configuration.yaml` on the
PVC, not in Git:

```yaml
recorder:
  db_url: !env_var RECORDER_DB_URL
  purge_keep_days: 10
```

`RECORDER_DB_URL` is injected from the `fqdn-uri` key of the
`home-assistant-db-app` secret generated by CloudNative-PG. The reverse-proxy
settings (`use_x_forwarded_for` and `trusted_proxies`) are managed by Home
Assistant in `/config/.storage/http`.

If the PVC is rebuilt from scratch, recreate those settings before expecting
history to work.

## Storage and backups

- `home-assistant-config` (ceph-block): full `/config`, including HACS,
  `.storage`, dashboards, and the legacy SQLite database.
- `home-assistant-backup` ReplicationSource: daily at 03:10 UTC to RustFS,
  retained 7 daily / 4 weekly / 12 monthly. The mover runs as root because
  `.storage/auth` is `0600`.
- `home-assistant-db` cluster: recorder history. Backed up by the
  barman-cloud plugin daily at 03:45 UTC.

## Networking

The pod uses `hostNetwork: true` with `dnsPolicy: ClusterFirstWithHostNet` so
mDNS/SSDP discovery and LAN broadcasts work, and it is kept off
`unraid-worker`. Istio terminates TLS for `hass.${SECRET_DOMAIN}` and forwards
to the service on port 8123.
